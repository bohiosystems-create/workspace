One integration: SQL Server

The agent connects to EstateMaster through the SQL Server database EstateMaster syncs with. No screen scraping, no file shuffling.
1
ReadOutputs, cash flows and actuals from the synced tables. The base case is read-only for the agent.
2
Write to a sandbox scenarioChanges go to a dedicated scenario (BHO_SBX), never the approved base case. EstateMaster picks it up on sync and recalculates.
3
Promote with approvalOnly an Investment Director can promote a sandbox scenario, and every write is audited.

Two-speed engine

Why the agent can run "infinite" scenarios
A
Fast engine: calibrated replicaBohio rebuilds the project's cash-flow logic and calibrates it against EstateMaster outputs. Thousands of scenarios per second, used for exploration, Monte Carlo and heatmaps. This demo runs on such a replica.
B
Truth engine: EstateMasterAnything that goes into a report or an IC decision is re-run in EstateMaster through the SQL Server integration and reconciled to the replica. Findings are flagged "verified" only after that.

Guardrails

Agent only edits a sandbox copy; promotion to the live model is a separate approved step.
Every read, write, recalculation and report is logged with user, channel, data source and timestamp.
Assumption changes are diffed against base and stamped on every report.
Replica drift check: if replica and EstateMaster disagree beyond tolerance, the agent stops and says so.

Outlook integration

How the agent gets context on assumption changes from email
1
Microsoft Graph, read-onlyAn Entra ID app with Mail.Read, limited by an application access policy to one project mailbox or folder (e.g. "Al Narjis"). The agent never sends or deletes mail.
2
Change notificationsA Graph subscription on the folder pings the agent when mail arrives; no polling of personal inboxes.
3
Extract, then proposeThe agent pulls the assumption, the new value and the sentence it came from. Changes are proposed, never applied silently.
4
Cited everywhereApplied changes carry the sender, date, subject and quote into the changelog, the IC pack and "why did this change?" answers.

What it reads, what it ignores

Reads: cost plans and tender returns, pricing notes, term sheets, planning feedback, leasing LOIs, programme updates.
Ignores: anything without a model assumption (HR, logistics, newsletters). Attachments are read only from allow-listed senders.
Low-confidence extractions are flagged for a person to confirm before they can be applied.
Mail stays in Microsoft 365; the agent stores only the extracted fields and a message link.
