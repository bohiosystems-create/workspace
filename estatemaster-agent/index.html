How the agent operates EstateMaster

Every return is calculated by EstateMaster itself. Bohio runs it on a server and drives it the way an analyst would, through its data links rather than the screen.
1
RunnerA Windows VM (Azure, Saudi region) with licensed EstateMaster and Excel, plus a Bohio runner service that takes jobs from the agent.
2
Write inputsThe runner opens a copy of the project model (BHO_SBX) and writes the scenario's assumptions into its live-linked Excel inputs.
3
Recalculate and read backEstateMaster refreshes the link and recalculates; KPIs, cash flows and report tables come back the same way, stamped with a job ID and stored in SQL Server.
4
ScaleOne run takes seconds. Stress libraries and sensitivity grids queue across several runners. The fast replica only screens; anything that is reported is re-run here.
!
Confirm with AltusUnattended use on a server licence, and whether EstateMaster exposes a native automation interface that could replace the Excel link. SQL Server stays for actuals and sales data.

Two-speed engine

Why the agent can run "infinite" scenarios
A
Fast engine: calibrated replicaBohio rebuilds the project's cash-flow logic and calibrates it against EstateMaster outputs. Thousands of scenarios per second, used for exploration, Monte Carlo and heatmaps. This demo runs on such a replica.
B
Truth engine: EstateMasterAnything that goes into a report or an IC decision is re-run in EstateMaster by the runner and reconciled to the replica. Findings are flagged "verified" only after that.

Guardrails

Agent only edits a sandbox copy; promotion to the live model is a separate approved step.
Every read, write, recalculation and report is logged with user, channel, data source and timestamp.
Assumption changes are diffed against base and stamped on every report.
Replica drift check: if replica and EstateMaster disagree beyond tolerance, the agent stops and says so.

Outlook integration

How the agent gets context on assumption changes from email
1
Microsoft Graph, read-onlyAn Entra ID app with Mail.Read, limited by an application access policy to one project mailbox or folder (e.g. "Al Narjis"). The agent never sends or deletes mail.
2
Change notificationsA Graph subscription on the folder pings the agent when mail arrives; no polling of personal inboxes.
3
Extract, then proposeThe agent pulls the assumption, the new value and the sentence it came from. Changes are proposed, never applied silently.
4
Cited everywhereApplied changes carry the sender, date, subject and quote into the changelog, the IC pack and "why did this change?" answers.

What it reads, what it ignores

Reads: cost plans and tender returns, pricing notes, term sheets, planning feedback, leasing LOIs, programme updates.
Ignores: anything without a model assumption (HR, logistics, newsletters). Attachments are read only from allow-listed senders.
Low-confidence extractions are flagged for a person to confirm before they can be applied.
Mail stays in Microsoft 365; the agent stores only the extracted fields and a message link.

AI providers

No engine choice: the router picks EstateMaster, a data query or an AI model per request, and the model tier by task (fast for commentary, smart for agent work, deep for IC narratives).
Claude (Anthropic Messages API) and OpenAI (Chat Completions API) can both be connected; if one fails, the other takes over. With neither, the rules engine still answers.
All engines share the same tool set: status, assumptions, stress, sensitivity, headroom, explorer, market, zoning, Outlook, capital structure, Excel, report, promotion request.
Production: keys live on Bohio's gateway, not in the browser; the model never gets write access to the base case.
