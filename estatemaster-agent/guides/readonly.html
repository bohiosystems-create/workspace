KINAN · EstateMaster agent (read-only)

Reads EstateMaster. Never writes to it.

What it is

This agent reads your EstateMaster exports, checks them, works out the effect of proposed changes and reports. It does not change anything in EstateMaster: every figure it shows as EstateMaster’s comes from an export, and every estimate is labelled as the agent’s own.

What to click

Daily feedWhat happened since the last export: proposed changes with their worked-out impact, stress tests, model reviews. Each row opens with details ›.

What the agent refuses, and why

Approving or rejecting a changeThis agent is read-only. It works out and checks the impact of each proposed change; the decision and the entry into EstateMaster are made by a person. The mock-API agent is the one that writes.
Assuming a missing inputIf the export has no cash flow, no land cost or no finance rate, the agent asks in the chat instead of filling the gap. A figure built on a guess would be presented as fact, so it is never produced.
Showing an IRR it cannot reproduceThe agent first proves that EstateMaster’s own cash flow reproduces EstateMaster’s IRR. If it cannot (within 0.05 points), it refuses to compute IRR changes and flags the model for review.
Reporting an IRR where none existsIf a scenario leaves the equity never recovering, the answer is “no IRR exists”, not a number from the AI.
Replacing EstateMaster’s figures with the AI’sAI estimates are cross-checked by a second model and overridden by the exact engine whenever the export carries a cash flow. The AI’s own figure is kept visible, labelled, so the difference can be seen.

Where the figures come from

Three kinds of figure appear, always labelled: EstateMaster’s (read from an export or the API, never recalculated), exact (computed by the agent from EstateMaster’s own cash flow, proved against EstateMaster’s IRR first) and AI estimate (two models, cross-checked; shown only when nothing exact is possible). Click any bold figure to see its working.
