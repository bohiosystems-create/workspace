# KINAN EstateMaster agent: standing rules

These rules hold for every change to this app. They come from the product owner and are not optional.

## 1. AI is always primary

- The AI reads the user's words and names the model cells. Rule-based parsing (`xcParse`, `xcFindLabel`, the router regexes) is the fallback for when no AI is connected. With an AI connected, the rules only propose a reading for the user to confirm.
- When the AI names a typed input cell for every change, its reading is used. A different rule-based reading is noted in the steps, never put to the user as a question.
- Rules may overrule the AI only on certain facts, never on judgement:
  - the cell is not a typed input (a formula, an output, a missing cell);
  - the value is impossible (a percentage over 100, a negative amount, a level 1000× off the current value);
  - the sentence states a direction ("drops", "+10%") and the AI moves the same line the other way;
  - the case/scenario cell the AI names is not the one the model runs on (`xcScenarioLive` picks the live one).
- Do not fix a misreading by adding another phrase rule when the AI path can carry it. Improve the AI prompt (`XC_READ_SYS`), the context it is given, or a certain check instead. New rules must be the no-AI fallback.
- When the AI's reading fails a certain check, the reason goes back to the AI and it reads again (twice at most); the rules do not take over.
- When no AI answers at all (every model, the retries and a second pass), the rules decide nothing: the AI's saved reading of the same sentence is used, or the rules' reading is put to the user to confirm.
- Every new tool or resolver that has to pick a line of a model (goal seek, sensitivity, feasibility drivers, reports) takes the AI's cell first and validates it with the same checks.

## 2. Financial modelling works like Claude for Excel

- Read the actual workbook: inputs, formulas, outputs, labels, units and formats.
- Change only typed input cells, or the assumption a formula carries: a number written inside a simple formula (Construction Costs =Units*190: the 190) is an input, moved by rewriting that number with the formula kept; a formula line the user names as a lever is moved by a factor on its own formula. Never answer "not computed" while a lever exists. Recalculate the whole workbook exactly with the formula engine (HyperFormula worker). Never estimate a figure on an uploaded model: it is exact, or it is reported as "not computed" with the reason.
- A workbook saved without recalculating (its stored results lag its own typed inputs, proven by a simple formula that gives another result on the file's own inputs) is recalculated on its inputs, and the user is told, with that cell, and asked if the inputs are not the ones meant.
- Extending the cash flow ("by N years") changes the workbook itself, as Excel would: new periods after the last on every timeline sheet, each line's formula carried on, totals, IRR/NPV ranges, names, charts and the input curves read by period stretched to the new end, then an exact recalculation; the extended workbook becomes the project's model (shown on the platform's sheets and downloadable). Numbers typed in the last period, an exit in the last period (or a hold-period input) and an unlabelled period length are asked with clickable answers, never assumed.
- Changes to a model's structure (extending the cash flow, a new line, an added sheet such as a refinance or a mezzanine, a fix to a contract) are Jadwa's only. KINAN relies on EstateMaster: its models change in EstateMaster and are exported again, and KINAN tests them (what-ifs, sensitivities, the analyst toolkit) without rewriting them. Jadwa works fully on the Excel workbook, which it may change. Before a change to a model's structure, the model as it is (workbook and record) is saved in the company database as a write-once version (`/api/store`, kind `version`: nobody replaces or deletes it); if it cannot be saved, the change is not made. What-ifs are not saved there unless the user makes one the model (“Make this the model”).
- The analyst toolkit (hold vs sell, return bridge, line over time and covenants, timing shifts, two-way grids, optimisation, Monte Carlo, mezzanine / refinance / waterfall / zakat overlays, trace, currency, new lines, fund roll-up) runs on the workbook itself: every figure is an exact recalculation. A result the model cannot give is said so (a year past its last period, an IRR its own IFERROR turns into 0, a currency conversion that moves the returns), never shown as a number. Amounts keep the model's unit (a sheet in SAR '000 holds thousands).
- Show every cell changed (sheet!cell, old → new) and every output moved, and offer the workbook back as an .xlsx with the change applied.
- Two models audit the recalculation after the answer. Their disagreement is shown, not hidden.
- One name, one figure: a headline (levered IRR, unlevered IRR, profit on cost) is the scheme's own figure, never a partner's (an LP net IRR, the sponsor's IRR or profit). An answer that gives a headline name another cell's value is flagged under the answer with both cells.
- The model map (on for every upload; Settings → Model map at upload switches it off): the workbook's structure is read once at upload (headline figures with their definitions, units per sheet, scenario switch, timeline, the cash flow behind each IRR, the hold input). The AI's reading is used where its proof on the workbook holds, the rules' otherwise; two proved readings of one figure are a question for the user; every entry is shown on a card and confirmed once; a correction in the chat is proved before it is used. Tools read the map instead of guessing the structure. After every what-if, each IRR is run again on its own proved cash flow and must give the figure the workbook reports; one that does not is flagged in the answer (a change to the hold input, which moves where the line ends, is not re-run).
- Never an estimate in the AI's own words either: an IRR the answer states must be the model's own figure or one the tools computed for that answer; any other is flagged under the answer as not computed.
- A currency conversion cannot move an IRR: lines the AI did not mark as money are added back only when the IRR then ends exactly where it was, and each is named.
- Never assume. If the workbook does not say, ask the user in the chat.
- One shared model record: every workbook made from a model (a contract fix, an extension, a new line or sheet, a what-if made the model, an earlier workbook restored) goes through `newModelVersion` and only through it. It keeps the model as it was (company database), and carries the headline cells, the map (moved by a row insert; read again only when the periods moved), the figures in the model's units, the inputs' roles, the user's verdicts and the regime. A tool never builds a new workbook record by itself.
- Inputs have roles: the AI tags each typed input once at upload (revenue, cost, leverage, rate, yield, timing, count, switch, other), kept in the map so the roles travel with every version. The debug's direction and threshold checks and the plausibility ranges read the role; the label's words are only the fallback when no AI answered.
- What was asked against what was done: a tool that does only part of the request, or something near it, says so with `noteGap` (shown as "Not as asked" under the answer), never a silent default (rounding, a nearest report, a dropped question). Every answer is then checked against the request itself (the AI; certain rules without one: a day, a year, a quoted or proper name asked and absent from the answer).
- Nothing the user names is swapped quietly. Every lookup of a named thing (a report, a project, a figure, a line, a series, a template, a dataset, an assumption, a case) goes through `matchNamed`: an exact name is used; one close name is used and the answer says how it was read; none or several is asked with the options (`missNamed`), never a default. A value the tool cannot take as given (a 31st, more grid points than it holds, a count above the limit) goes through `noteAdjusted` / `a33Clamp`; a result picked because none was named goes through `a33PickFig`. A default is used only when the user named nothing, and the answer says which. tests/t_asked.mjs calls every tool with unknown names and out-of-range values.

- A figure is not one number in one cell. A typed line is read as its whole row: a row that is 0 where the line is off (occupancy while it is built) is judged by its first value that is not 0 (its scale, whether it is a percentage, how far a change is off), and a level set on it keeps its periods at 0 unless every period is asked. A cell that holds an error (#NUM!, #REF!, #DIV/0!…) is said with its code and what it means, at upload and after a change; it is never read as a figure the workbook lacks. Errors already in a workbook are traced to their cause (`errdiag`): the cell a chain of errors starts from (its own inputs fine, or its own formula broken), why it errors from its formula and the input that breaks it, and the cause tested by recalculating without it, the workbook left as it was; the cells that only inherit it are counted under it. Numbers typed as text are numbers in any digits; a unit word first in a row with one figure after it (Units, GFA, NLA, Years) names that figure.
- One picture of the workbook, never thinner than the workbook. The engine worker builds it once per load (`picture`): every cell as the engine holds it, with the cells of a circular reference restored to their formulas and edges (`CIRC`, `fmlOf`/`hasF`/`preOf`/`depOf`, never a raw `hf.getCell*` for the graph), the cells a dynamic array spilled into as the engine's, every labelled formula result as an output (an NPV, an LP IRR, a DSCR counts: an input that moves only those is not without effect), every Excel table as records (a row keyed by its first text, two rows with one name told apart), dates by format or by value (a run of serials in General format, its first cell included). Every check and view reads that picture: the debug's unused/direction/no-effect/duplicate checks, the trace, the metric formatters (a kind for every output, not only the headline keys), the portfolio views (an error shows its code), the fund dates. A ratio formula in General format (=B2/B1-1, =IRR(…)) is a fraction whatever its size. A cell that reads another workbook is said so, naming it. A follow-up tool runs on the last what-if's cells (`A33BASE`, `a33Chain`) or the last extension (`LASTEXT`) and says which version it ran on (`a33ver`). tests/t_picture.mjs holds one synthetic workbook per Excel feature (loop, table, spill, dates by value, cross-sheet array, merged header, names, external link) against hand calculations; a new Excel feature met in a model gets its workbook there first.
- The picture carries what the cells mean, from one source, and every tool reads it there: each sheet's money unit (`xcScaleAt`: the map's units, else the sheet's own heading; SAR '000 is said in currency in the trace, the line over time, the reports and the map card), the timeline's period (`xcPeriod`, `xcBounds`: a period input moves in whole periods inside the timeline, exits are asked and shown in the hold's own unit, months or quarters roll up into years), the inputs' roles (`xcTimingIn`; a direction is certain only on a path that is all cost or all revenue: an income yield is revenue, an area that only drives cost has none), the case switch (a word or a number, found from what reads it, proved, run by name; the inputs of the other cases are tested under their own case), calendar constants (EDATE's months, `^(1/4)`, the periods in a year) which are never inputs, and the model's own words for its figures (`metLabel`: a fund's “Gross IRR” keeps its name). tests/t_meaning.mjs holds one synthetic workbook per kind of meaning against hand calculations; a new kind met in a model gets its workbook there first.
- The engine is checked, never taken as the workbook. A defined name built on OFFSET or INDIRECT is put back into the formulas that use it; INDIRECT over a range on a sheet picked by name is followed; a cell the engine here cannot compute (its own #ERROR!, a function it lacks, an INDIRECT it cannot follow) is a gap: the server engine takes the workbook over when it computes those cells, else the cell is said “not computed here”, never the workbook's error. The server engines are tried in order, Excel itself first (`/api/xl`, Microsoft Graph, a session that saves nothing; docs/excel-engine.md), LibreOffice next (`/api/lo`): each takes a workbook only when its own check reproduces 99% of the results the file stores, and the answer names the engine (tests/t_xl.cjs, tests/t_xlengine.mjs). An error the app wrote into a file saved without results is not one Excel saved. An IRR Excel's 10% start guess does not reach is #NUM! as in Excel, with the rate that exists and a guess tested as the fix. Ops that read the workbook (the picture, the signature, the error trace, the switch scan) start from it as it stands, not from a what-if a run left in place.
- The request has one contract, resolved before any tool runs (`ctxResolve` in `handle`), and every builder reads through it (Layer A): the project the user names (two words of its name, one distinctive word, or its Arabic name from the model map) is the one answered; “after that change”, “on top”, “… now?” or a currency the model was converted to set the export's view (`xvSet`), so `x.out` is that version's figures for every report, deck, email, section, chart and check without any of them knowing, and `xcCall` carries the same version's cells; a case the question names (“on the Downside case”) runs the tool on that case; a question without such words clears the view. The raw uploaded figures (`x.out0`) are read nowhere else. A version is named through `ctxVersion`; what was asked and could not be applied is said. tests/t_context.mjs and tests/t_layers.mjs hold every tool and every builder (BLOCKS, RPTS, the email, the deck) to it.
- Every number that comes from outside the workbook reaches the cell in the cell's own unit and scale through one conversion (Layer B, `qtyTo` / `qtyRange`): a covenant, a range, a ±% move, a target, a hurdle, a bound, a document's figure. The target decides (a fraction or a whole percent, a sheet in '000), never the tool, and the reading is said when it changed the number. A result the workbook stores as a whole percent is shown as it is (`a33Whole`, `a33Pts`), never ×100. No tool parses percent or scale on its own: tests/t_layers.mjs freezes the arithmetic left in the toolkit and runs each number-taking tool with the figure in both units.
- What the documents state lives in one store (Layer C, `docTerms`): a lease's or term sheet's items and an agreement's register come out in one shape, and every reader (the chat answer `docAnswer`, the covenant check `docCovenant`, the report section, the slide) reads it there, never a document's own list. A covenant a document states (a minimum DSCR) is checked on the line it binds at upload; a question about one term answers with that term and its quote; a question about the model as a whole answers with every term.
- One search for a target along a lever (Layer D, `xcBracket`): a point where the model gives no figure (an IRR with no sign change) is searched past, the computable edge found by bisection and the sign change looked for among every computable point; the gap is said with the answer. “Does not reach” is said only when every computable point is on one side. Every goal seek and break-even goes through it.
- A fix to a cause lands at the shared layer and its test enumerates the callers from the code (TOOLS, BLOCKS, RPTS, STRUCT_TOOLS, the source scans), never from a hand-written list: a new tool, builder or conversion site fails the test until it is placed.
- A family is fixed by its written list, not by the case found: before the fix, list every case of the family in a generator whose truth is known by construction (tests/fixtures/gen/gen_valuemeaning.py, the prompt pools in tests/t_answerkind.mjs), test every caller over the whole list, and measure once on a pool written before the fix and never tuned on. A shared layer is tested on its outputs for every kind of input, not only on whether callers reach it.
- What a number in a cell means comes from one classifier (`meanOf`, read per cell by `xcMean`): its row's own label first, then its column heading, then the sheet's title; an amount takes the stated unit, a price per sqm or per unit, an area, a count, a rate, a multiple or a time never does. A sheet's unit is read only inside `xcMean` (`xcSheetUnit`); a display shows the amount meant, or the cell's own number (with the sheet's unit said when its kind cannot be read), never a guess. A unit word must not follow a letter (“(sqm)” is no unit).
- Without the AI, a rules reading answers only a request that shows that kind of answer (`askedKind`, `intentKind`, `kindGate` in handle0 for readings made from the user's words): a request the rules cannot read is said, never answered with another kind (the headline figures for a goal seek, a sensitivity for a hold-or-sell). Readings the AI chose and forced intents (buttons) are not gated; the AI's answer is checked after it (askGapCheck).
- Reports lean on the AI for words, never for figures: with an AI connected every report gets its narrative (only the user’s own “no narrative” or “without a narrative” turns it off (narrAsked; the designer’s narrative switch is off by default and is not a request)), the AI reads audience and emphasis into the design (`design_report`), and every number the narrative writes must be one the report shows (`narrCheck`, to the precision written): a wrong one is sent back once, then its sentence is left out and the report says so. A provider out of API credit is set aside (`AICREDIT`): the rules answer at once, the chat says so once, and it is tried again after 15 minutes or from Settings. tests/t_narrcheck.mjs uses a stand-in AI that writes wrong numbers on purpose.
- Before a push, `bash tests/run.sh core` also runs the tests whose recorded run executed a function this change edits (tests/touched.py over tests/coverage_map.json); a function no test runs is printed and needs a test. Rebuild the map after adding tests: `COV_OUT=<dir> NODE_OPTIONS="--import $PWD/tests/cov_preload.mjs" bash tests/run.sh full`, then `python3 tests/touched.py --build <dir>`.
- A change of structure is described from the files, not from what the tool meant to do: every workbook made from a model goes through `newModelVersion`, which reads the two workbooks (`wbFileDiff`: sheets added or removed, typed numbers changed or new, formulas changed) and the answer states it; a claimed effect the files do not show is not said (“move the exit” when the sale is timed by an input the extension does not change says so, naming the input). A headline's value is read at the model's own headline cell on the new workbook, never the reader's figure under the same name on a sheet the change added; an overlay's own figure (“Equity IRR after zakat”) is a labelled result, never the headline. A version chain across changes of structure is bridged version by version. Builders read the meaning layer: an overlay's IRR follows the timeline's period (a quarterly model's IRR is annualised as the model's own). Every table names a headline in the model's own words (`exLab`/`metLabel`), a chart speaks the unit the user asked in, and a count of scenarios has no change called out. tests/t_effects.mjs iterates `STRUCT_TOOLS` (a new builder fails until it has a case).
- The demo model and an uploaded workbook are walled apart in code, at the section itself: a report section built on the demo model, called by any path on an uploaded workbook, gives its workbook section or says it needs the full model (`rpPlan`, the walled `BLOCKS`); every section declares its scope (`BLOCK_SCOPE`: portfolio sections list every project by name). tests/t_wall.mjs runs every section and every report in two sessions, the demo model as shipped and moved, and nothing of an uploaded project may differ. A demo section whose meaning a workbook has (scenarios side by side → the what-ifs recalculated on it) is swapped through `WB_FOR`, never left as an empty report.
- Naming things in a request is weighed, not counted: a project's own phrase (“Al Manar”) outweighs one word of another project's name met alone (“the main risk”) in `ctxProjectNamed`; two projects named equally while a third is open is said. A report name held by several reports is the one on screen, else the latest made (`rptByName`). A tool on a tested version names that version (`svBase`), never “the workbook as uploaded”. tests/t_round49.mjs.
- A rule is enforced in code, not only in a prompt or a tool description. Reports and alerts go to internal addresses only, checked at the one place that sends (`runReport`) and where recipients are saved; a jurisdiction or a hurdle is recorded only when the user's own message says it or confirms it (`userSaid`). A return's move is judged in points, not as a share of itself. Technical errors reach the user in plain words through `plainErr` (every answer and every toast); a file's name is cleaned of any path wherever a file comes in. Once the user has asked, only old suggestion chips are hidden, never an answer's own buttons.

## 3. Working rules

- EstateMaster is the trusted layer.
- Test fixtures are synthetic. Never commit client workbooks.
- Each model family has a synthetic replica with golden answers from LibreOffice (tests/fixtures/golden/props.json, swept by CI). LibreOffice is installed only through `tools/install_lo.sh` (the LibreOffice team's archive, 25.2 or newer, or the job fails) in CI, and from Debian 13 (backports when newer) in the server engine (lo-service/Dockerfile). A correction a user makes to a reading is logged (Settings → Corrections) and becomes a test case.
- Bug impact in test reports: a figure that comes out wrong is high impact by definition (an IRR, a profit, a cell value, a figure in a report or a view), whatever the tool, unless the difference is negligible (rounding, the last digit shown). Medium and low are for bugs that leave every figure right: a missing note, a wording, a slow answer, a layout fault.
- Before a push run `bash tests/run.sh core` on its own (no other suite against the same port). CI runs the quick suite on every push and the full suite nightly; deploy only after GitHub CI is green on that commit.
